# Full-scale model verification

Verifies the generated full-scale accelerators of Table 3 (`designs/hls/fullmodel/`, generated by `forgebench/fullmodel` from
`designs/configs/fullmodel/`) by Vitis HLS C simulation of the saved `top.cpp` / `top.h`:

```text
designs/configs/fullmodel/*.json -> forgebench generate -> designs/hls/fullmodel/<project>/top.cpp
  -> verification/fullmodel/verify.py   (C simulation vs two PyTorch references)
```

The verifier executes the saved generated source. It never substitutes a dedicated model, a verification template or a PyTorch
implementation for the device under test. Each run compares the accelerator with

1. an integer-code fixed-point PyTorch graph of the same arithmetic: every compared code must match exactly, and
2. an independent FP64 PyTorch graph: relative L2 error <= **5%** at every observed tensor (an all-zero FP64 tensor uses a 0.1
   absolute fallback, since relative L2 is undefined).

How the references are built: [REFERENCE_IMPLEMENTATION.md](REFERENCE_IMPLEMENTATION.md).

## Designs and results

The 14 Table 3 designs (`manifest/designs/fullmodel.csv`): ResNet-18/34/50/101/152 full-buffer `<32,10>` (RND/SAT) and tiled
`<16,5>` (TRN/WRAP), 10 seeds each (42-51); Llama-3-8B prefill + decode at ctx 2048 and 8192, `<32,10>`, 3 seeds each (42-44),
4 prefill tokens + 2 decode calls per run. ctx 2048 / 8192 set the K/V-cache capacity and the generated interface dimensions;
both run the same six tokens, so they are not 2048- or 8192-token prompt runs.

Every run passes both checks. Per-run summaries and input manifests: `results/verification/fullmodel/<group>/<project>seed<n>/`;
`make table3` turns them into Table 3's error columns (maximum over seeds of the final-logit errors).

Relative L2 error is calculated as:

```text
relative_l2 = ||y_hls - y_fp64||_2 / ||y_fp64||_2
relative_l2_percent = relative_l2 * 100
```

Here, `y_fp64` is the output of the independent FP64 PyTorch graph. The HLS
output is stored as signed fixed-point integer codes and is converted to real
values before comparison:

```text
y_hls = hls_integer_code / 2^(W - I)
```

Therefore, `ap_fixed<16,5>` uses `hls_integer_code / 2^11`, while
`ap_fixed<32,10>` uses `hls_integer_code / 2^22`. For a tensor with elements
indexed by `i`, the calculation can also be written as:

```text
relative_l2 = sqrt(sum_i((y_hls[i] - y_fp64[i])^2))
              / sqrt(sum_i(y_fp64[i]^2))
```

The run verdict requires every observed intermediate tensor and every populated K/V-cache entry to pass, not only the final logits.

## Run

Needs `pip install -e '.[verify]'` (torch) and Vitis HLS 2024.1 on `PATH`.

```bash
make verify-fullmodel OUT=<new dir>                  # all 14 designs, all seeds (106 runs, ~2.5 h)
make verify-fullmodel OUT=<new dir> ONLY=RESNET50    # a subset (regex on <group>/<run>); SEEDS="42" for one seed
FULLMODEL=<that dir> bash verification/experiments/collect_results.sh   # compact copy into results/verification/fullmodel/
```

One design directly:

```bash
python verification/fullmodel/verify.py --family resnet50 \
    --project designs/hls/fullmodel/RESNET50_config_ap_fixed_32_10_ --seed 42 --output <new dir>
python verification/fullmodel/verify.py --family llama3 \
    --project designs/hls/fullmodel/LLAMA3_8B_PREFILL_ctx2048_config_ap_fixed_32_10_ \
    --decode-project designs/hls/fullmodel/LLAMA3_8B_DECODE_ctx2048_config_ap_fixed_32_10_ \
    --prefill 4 --decode 2 --timeout 14400 --threads 16 --seed 42 --output <new dir>
```

A Llama run allocates a ~33 GB parameter store in its output directory. `--inspect-only` checks source hashes and interfaces without
running (reported as `INSPECTED_NOT_EXECUTED`, never as a pass). Output directories must be new. `verify.py` only accepts sources
registered in `references/contracts.json` (SHA-256 of every `top.cpp` / `top.h`); register changed sources with `register_sources.py`.

## Tests and scope

```bash
make test        # includes verification/fullmodel/tests
```

These results establish functional Vitis HLS C-simulation agreement for deterministic synthetic parameters. They do not establish
pretrained accuracy, full-model RTL co-simulation, FPGA execution, or accelerator performance.
